# Code Quality Constitution

この憲法は、ソースコード、設定、スキーマ、互換処理を含む実装全体に適用します。

## デッドコードを残さない

- 現在の仕様で使用されず、実行経路や参照元から到達できないコードは必ず削除する。
- 未使用の設定、型、export、互換処理、無効化された分岐、コメントアウトされた実装もデッドコードとして扱う。
- 「将来使うかもしれない」という理由では残さない。必要になった場合は履歴から復元するか、その時点の要件に合わせて実装する。
- 実装を置き換えた変更では、置き換え前の実装と、それだけが使用していた関連コードも同じ変更内で削除する。

## 例外として残す場合

- 外部からの呼び出し、実行時の動的参照、段階的な移行、互換性の維持など、現在参照されていないように見えても必要であることを確認できる場合に限り残せる。
- 例外として残すコードの直近に、次の内容をコメントとして記載する。
  - 未参照に見える理由。
  - 何が、どのタイミングで使用するのか。
  - 削除できる条件、期限、追跡先、または恒久的に必要となる契約。
- 理由を具体的に説明できないコードは例外とせず、デッドコードとして削除する。
- 静的解析やテスト対象から除外する場合も、同じ根拠を除外設定の近くに記載する。
